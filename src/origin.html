Integration Checklist
What to integrate FIRST — in this exact order. Do not skip a phase. Do not build until Ready to Build. Owner must be a person, not a team. Every row starts as To confirm.
Checklist — in integration order
Filter by phase. Tick the status per row as the customer confirms it. Status is in-page only — it does not send anything anywhere.
⚠ Message — Masters
Do not integrate any transaction until its masters are confirmed. Sales orders need Customers + Items. Purchase orders need Vendors + Items. Inventory journals need Items + Warehouses. Production orders need Items + BOM. If a master is wrong, every transaction built on it is wrong. Masters first, transactions second — no exceptions.
⚠ Message — Parameters
Parameters must be set before the module is integrated. 812 parameters, Steps 0–28, per legal entity. If a parameter is wrong, the integration will post wrongly even though the field mapping is right. Check in Parameter & COA Mapping: module → parameter → value → status. No parameter = no integration for that module.
⚠ Message — COA Mappings
COA must be mapped before any GL posting. Standard 12 / Customer 5 / Both 17 (sample). Every journal, invoice, payment, and bank statement posts to a MainAccount. If the COA is not mapped, the journal fails or posts to the wrong account. COA first, then INT-07 (GL Journal), then INT-08 / INT-09 (invoices / payments), then INT-10 (bank statements).
How to use this checklist
  1. Work top to bottom — Phase 0 first, then Phase 1, then Phase 2, then Phase 3.
  2. For each row: customer confirms module + functionality + fields + owner (a person, not a team) → set status to Ready to Build.
  3. Build only Ready to Build rows. Test each one in TEST-COMPANY-01, 3–5 rows max.
  4. When all 8 Final Gate checks pass (see Pilot Pipeline), set status to Done.
  5. Client Secret NEVER in this file. No live D365. No direct SQL.
